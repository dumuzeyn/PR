# Архитектура PhotoRedactor

## Правило размера

Исходный Python-файл должен содержать не более 500 строк. Проверка выполняется в `tests/test_architecture.py` локально и в GitHub Actions. Новый модуль выделяется по пользовательской или предметной ответственности, а не по случайному количеству строк.

## Публичные входы

- `photoredactor.app` экспортирует `PhotoRedactorApp` и функции запуска.
- `photoredactor.core` экспортирует модель документа и все операции ядра.
- `photoredactor.history` экспортирует команды undo/redo и `History`.
- `photoredactor.ui.tool_options` и `photoredactor.ui.tool_palette` сохраняют прежние публичные компоненты.

Эти фасады остаются небольшими, чтобы внутренние модули можно было менять без переписывания вызывающего кода и плагинов.

## Интерфейс

`PhotoRedactorApp` собирается из mixin-модулей в `photoredactor/app_mixins`. Каждый модуль отвечает за один пользовательский процесс: запуск, меню, холст, рисование, выделения, документы, трансформации, фильтры, маски, векторные объекты, ретушь или плагины. Общие импорты и константы находятся в `app_shared.py`.

## Ядро

- `layer.py` содержит модель слоя.
- `document.py` собирает документ из модулей `document_mixins`.
- `geometry_ops.py`, `selection_ops.py`, `render_ops.py`, `retouch_ops.py`, `text_ops.py`, `shape_ops.py`, `filter_ops.py`, `content_ops.py` и `adjustment_ops.py` содержат чистые операции по областям ответственности.
- `core_shared.py` содержит общие типы, константы и низкоуровневые преобразования.

Операции ядра не зависят от Tkinter. Интерфейс вызывает их через публичный фасад `photoredactor.core`.

## История

Команды свойств и структуры находятся в `history_base.py`, команды пикселей, масок и состояния — в `history_patches.py`, а стек истории — в фасаде `history.py`.

## Тесты

Крупный набор запуска интерфейса разделён на стартовые процессы, элементы управления и взаимодействия с холстом. Из-за ограничения Tcl/Tk на Windows каждый UI-сценарий запускается отдельным процессом в GitHub Actions.
